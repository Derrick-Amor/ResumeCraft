# ResumeCraft 风险清单

> 依据：PRD V1.3 第 20 章 14 条风险（R01–R14 原文对齐）+ 执行层补充风险（E01–E14，来自计划包核对与本轮文档比对）。
> 用法：每卡开工时扫一遍"首次暴露的卡"命中自己的行；验收时核对缓解动作是否已留证据。
> 风险不会因为"已记录"而消失；只有留下证据文件才算缓解。

---

## 2. 执行层补充风险

| ID | 风险 | 首次暴露的卡 | 缓解动作 | 判定标准 |
|---|---|---|---|---|
| E01 | **Canvas 测量与 DOM 行盒不一致会推翻测量方案**（R10 的后果级风险）：若晚发现，TC-007 及下游 TC-010/TC-011 全要返工 | TC-006（第一件事） | 先做对照小样再写引擎；结论写 `docs/verify/canvas-vs-dom.md`；不通过即升级变更单，禁止带病进 TC-007 | 对照表出具（行数差、宽度差、偏差原因）；Amor 认可后才放行下一卡 |
| E02 | **pdf-lib 中文必须 TTF**：OTF/CFF 会嵌成 CIDFontType0，Chrome 不渲染（已核实的坑） | TC-010 | 强制 TTF + `subset:true`；字体文件纳入 `src/assets/fonts/` 并登记许可 | 中英各一份 PDF 在四阅读器打开无缺字；导出后回读冒烟在 CI 可跑 |
| E03 | **mammoth 对表格/文本框/浮动图片能力未知**：可能导致导入承诺无法兑现 | TC-012 | 样本先行；能力边界写进用户可见的已知限制（4.2、12 章） | 每类样本有"支持/部分支持/不支持"结论，且产品内有对应提示文案 |
| E04 | **工程未初始化导致所有卡暂无"机器证据"**：当前除 TC-001 外无 lint/type-check/test/build | TC-001（本卡例外）、TC-002 | TC-002 建四门 + `verify:*` 占位；TC-003 起每卡必须贴命令原文 | TC-002 后 `pnpm lint && pnpm type-check && pnpm test && pnpm build` 空跑全绿 |
| E05 | **单一主控上下文膨胀**：约定被遗忘、卡序错乱、重复派单 | 每 2–3 卡（首次在 TC-002→TC-016 之间） | 按 TAPD 规范 §11 更新 `docs/plan/PROGRESS.md` 快照；关键决策 D1–Dn 逐条登记 | 连续 4 小时以上中断后，仅凭 PROGRESS.md 可复述"在哪/待确认什么/下一步" |
| E06 | **严格串行下单卡过大导致反复打回**：L 卡（003/005/006/007/008/009/012/013）跨多个子能力 | 任意 L 卡 | 只允许卡内拆子步，不新开卡逃避验收；每子步先跑自身单测 | 同一卡打回 ≤2 次；第 3 次即停并升级 Amor（规范 §4） |
| E07 | **git 仓库归属冲突**：项目目录位于家目录仓库 `C:/Users/D.Amor`（remote=`Amor_code`）之内，项目自身无 `.git`；直接 `git init` 会形成嵌套仓库 | TC-002 | 由 Amor 拍板三种处置之一（独立建仓/迁出/接受嵌套并改验收命令） | 决议写入 TC-002 派单；此后"git status 可证"类验收有明确执行方式 |
| E08 | **文档漂移**：PRD / 任务分工 / 执行规范 / 计划包四份口径不一致，子 Agent 各按一套理解执行 | 每卡（本轮已发现 4 处，见 `docs/handoff/TC-001.md` §5） | 卡内以"任务卡 + CONTRACT"为准；发现冲突先提冲突说明，不改基线文档 | 每卡交接报告 §5「与 PRD 不一致处」必须填写（无则写"无"） |
| E09 | **TAPD 状态流转未实测**：`update_story_or_task` 对新建需求正常，但 `developing/status_2/status_3/resolved` 未在真实卡上跑过；示例需求曾 404 | TC-001 派单时首次验证 | 首次流转失败即按 TAPD 规范 §5.6 降级，TASKS.md 升为主账 | TC-001 卡有"状态流转成功/降级"记录；三方对账（TAPD=TASKS=git）可执行 |
| E10 | **UI 组件库未定阻塞控件链**（外部前置 E3）：TC-004 及其后所有控件无法开工 | TC-002 小样 → TC-004 | TC-002 出小样后暂停，Amor 拍板再收尾；结论回写 PRD 13.1#3 | 拍板结论有书面记录；TC-004 派单时已引用该结论 |
| E11 | **导入样本未到位**（外部前置 E1）：TC-012 无样本即无法验收 | TC-012（M4） | 在 M2 结束前一周收取（TASKS §3）；样本清单与脱敏要求已固定 | 六类样本齐备并落盘；缺任一类则 TC-012 标"阻塞"而非"通过" |
| E12 | **字体子集体积与加载时序**：影响首屏与测量可用性（字体未就绪即测量＝测量不可信） | TC-006 | 显式 `FontFace` 加载完成后再允许测量；子集范围与体积记录 | 首屏加载预算有实测数值；字体未就绪时的降级标记可见 |
| E13 | **DOCX 标记协议未定**：TC-011 埋点与 TC-012 读回互为前提，协议晚定则两边返工 | TC-011 | 先出 `docs/docx-mark-protocol.md`（命名 + 版本号规则 + 受损判定）再写代码；协议变更必须升版本（CONTRACT §7.5） | 协议文档在 TC-011 编码前存在；TC-012 按该文档实现读回 |
