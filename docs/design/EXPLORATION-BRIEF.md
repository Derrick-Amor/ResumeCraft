## 1. 为什么要开这个口子

上一轮的 8 张稿，颜色换了四版、圆角改了 2px、加了 2px 位移——**观感几乎没变**。
原因不是设计师不敢改，是**可动的维度已经被锁完了**：

| 维度 | 当前锁定值 | 出处 | 后果 |
|---|---|---|---|
| 中性色 | `#f9f9f9 → #2b2b2b` 六阶 | PRD 6.2 | 整个界面的明度骨架不能重排 |
| 圆角 | 2 / 4 / 8 / 12 | PRD 6.2 | 出不了"圆润"或"硬朗"两种气质 |
| 阴影 | 2 / 4 / 8 / 16 四级 | PRD 6.2 | 出不了"无阴影扁平"或"重浮层" |
| 字号 | 12 / 14 / 16 / 20 / 24 / 28 | PRD 6.2 | 出不了大标题、细密列表两种极端 |
| 间距 | 4px 网格 2–32 | PRD 6.2 | 密度不可调 |
| 动效 | 100 / 150 / 200 / 300ms | PRD 6.2 | 出不了"几乎无动效"或"明显编排" |
| 主色 | 单一主色，静态面积 ≤ 0.42% | 上一轮裁决 | 出不了双色、色块分区、彩色侧栏 |
| 布局 | 五区域 44 / 264 / 1fr / 280 / 28 | PRD 6.3 | 尺寸区间只有 ±20px，等于固定 |

**结论：这套规则适合"收敛"，不适合"探索"。** 之前把所有探索都塞进收敛规则里做，所以每一版都长得像上一版。

## 2. 探索期临时解禁（本轮有效，选定后全部回收）

- **中性色**：可重排明度骨架，可出现暖白 / 冷灰 / 深色区块（但仍需保证正文可读）
- **圆角**：0–24px 自由，可出现胶囊、超大圆角
- **阴影**：可完全取消，也可加重到明显浮层
- **字号**：可引入 32 / 40 级标题，可整体加大或缩小
- **间距**：可打破 4px 网格，可用非均匀密度
- **动效**：可引入 400–600ms 编排、入场序列、视差位移（**仍禁回弹曲线**）
- **主色**：可多色、可大面积色块、可给侧栏上色、可用第二强调色
- **布局**：五区域尺寸与结构可重排；可试"无侧栏""双栏""顶部导航 + 卡片流"

## 3. 仍然不可协商（任何版本都不许破）

1. **禁 emoji 作功能图标**——图标一律 SVG
2. **禁紫→粉渐变主视觉**，禁"渐变 + 发光 + 毛玻璃"三件套
3. **禁空洞占位文案**（Lorem ipsum / Welcome to）
4. **正文可读性**：14px 正文对比度 ≥ 4.5:1（这条是人命，不是审美）
5. **画布即结果**：A4 纸面必须与导出 PDF 同色，纸内不得出现 UI 装饰

## 5. 参考对象与"借什么"

| 参考 | 借什么 | 不借什么 |
|---|---|---|
| Rezi | 极简骨架、内容优先、单一强调色、密度高 | 紫渐变主视觉 |
| Canva | 圆润形状、色块分区、元素卡片的"可拖动感"、hover 预览 | 拟物插画、彩色大 banner |
| Linear | 无边框 + 微阴影、悬浮工具条、克制的字重对比 | 深色优先 |
| Notion | 大留白、打字机式编辑感、侧栏极轻 | 无限层级嵌套 |

> 三个版本至少要覆盖三种不同气质：**极简（Rezi）、圆润（Canva）、工具（Linear）**。

## 6. 结构红线（2026-10-24 定，三套方案都必须遵守）

1. **A4 纸宽 794px 是常量。** 宽度不够时，面板**覆盖**纸，不许**挤压**纸。
   验收：1280 视口下纸的渲染宽度必须 = 794（`getBoundingClientRect().width`）。
2. **Paper 与 CanvasOverlay 必须是兄弟节点。** 选中框、插入线、角标、辅助线一律画在 overlay 层，
   不得进入纸的 DOM；overlay 元素带 `data-export-hide`。
   验收：导出快照与纸节点快照 diff = 0。
3. **07 溢出处理不用 modal**（2026-10-24 裁决）。它要回答"这几行往哪让"，用户必须同时看到出血行与三个选项。
4. **hover 只允许改色/边框**；任何"揭示新内容"必须由 focus 或 click 触发（键盘可达）。
5. **主色必须 9 档一起改**（primary / light-3/5/7/8/9 / dark-2 / subtle），只改 3 个会让 EP 的 hover/disabled 留旧色。
6. **界面字体 ≠ 纸面字体**：`--font-ui-*` 与 `--font-paper-*` 分开命名、永不互相引用。界面标题可用子集化衬线；纸面必须完整字重嵌入，否则导出 PDF 会 fallback。
7. **图标只有 16 / 24 两档**，锁 Lucide 1.5px；业务代码禁用 `el-icon`（它自带 font-size / vertical-align / display 三层叠加会毁对齐）。20px 档砍掉——1.5 的 stroke 在 20 档实际只有 1.25px，1x 屏发虚。
8. **正文 ≥12px 且 ≥4.5:1**；mm / pt 是真值，px 只在 100% 缩放时标注（`px@100%`）。页面上禁止出现假的比例数字。
9. **溢出处理界面永远贴底**：溢出的语义就是"超出页底"，界面跟着语义走，不做居中弹窗、不做自动翻边。

## 7. 裁决记录（2026-10-24，team-lead）

| # | 争点 | 裁决 | 依据 |
|---|---|---|---|
| R1 | 07 溢出处理用不用 modal | **不用**。贴纸下边（或上边）的条 | 决策变量是几何后果（收回 7mm / 仍缺 11mm / 底部留白 62mm），离开出血行位置无法判断；塞缩略图也不成立——18mm 在 200px 宽的缩略图上不到 14px |
| R2 | A 的页边批注在 1280 放不下（右侧只有 24px 沟槽） | **不做右侧卡片，改成贴纸下边的批注条** | 与 R1 同构：批注属于"纸的边"，不属于"纸的旁"。这样 A 在 1280 不丢功能，启用门槛不必抬到 1440 |
| R3 | 自建 hover 压暗 8% vs EP hover 变亮 30%，方向相反 | **主操作按钮一律自研，hover 统一「变亮 12% 白」；EP 的 `el-button--primary` 进 lint 白名单禁用** | 统一方向而不是统一色阶：EP 的 30% 跳变太大，压暗在 A 的近黑主色上 ΔL* < 0.5 看不出。禁用 EP 主按钮从源头消除二义，代价 0 行 |
| R4 | 断点只有宽度，B/C 吃高度 | 高度断点：**≥900 → 抽屉 240；800–900 → 200；<800 → 折叠到 40** | 1366×768 上 C 的纸只剩约 380px，等于一页只能看 1/3 |
| R5 | A 检查态 1280 装不下（差 2px） | A 检查态右栏 **320 → 296** | 56+24+794+24+296+16(滚动条) = 1210 < 1264，余 54 |

### R3 修正（2026-10-24 二次裁决，覆盖上表 R3 的"统一变亮"）

**不批"全局把 hover 改成变亮 12%"**，因为它会在中明度主色上打穿白字对比度：

| 主色 | 变亮 12% 后 | 白字对比 | 判定 |
|---|---|---|---|
| `#107093`（现） | `#2d81a0` | **4.41** | ✗ 破 AA |
| `#191a1c`（A） | `#353738` | 11.5 | ✓ |

正解是**方向由明度决定，不由偏好决定**：

> `--rc-color-primary-hover` = 主色 **L\* ≥ 20 时压暗 8%**（保对比度）；**L\* < 20 时提亮 12%**（压暗在近黑上 ΔL* < 0.5，看不出）。
> `--rc-color-primary-active` 同理，幅度加倍。
> EP 的 `el-button--primary` 仍按 R3 禁用；其 light-3（+30% 白）只服务 disabled/plain，不参与 hover。

结论：**现存 `tokens.css` 不改**（`#107093` L\*=38，压暗是对的）；只有采纳 A 时，A 的色板用提亮分支。

## 8. 变量分组（2026-10-24 补，四组互不引用）

| 组 | 前缀 | 为什么必须独立 |
|---|---|---|
| 界面字体 | `--font-ui-*` | 只服务 chrome，可子集化 |
| 纸面字体 | `--font-paper-*` | 必须完整字重嵌入，否则导出 PDF fallback |
| 浅底语义色 | `--color-*-on-light` | 现有四色（4.5:1 达标）只对白/浅底成立 |
| 深底语义色 | `--color-*-on-dark` | 警告 `#a86400` 在 `#151A1D` 上只有 **3.74:1**，必须换 `#D99A4E`（7.25:1） |

> 教训：一份语义色不能同时服务浅底和深底，就像一份字体不能同时服务屏幕和 PDF。

## 9. 评审口径（写给自己，避免第三轮再得到"都差不多"）

07 收敛成"贴底"之后，8 屏里 **04/05/06/07/08 五屏在三套方案之间同构**，真正分得开的只有 **01 编辑器 / 02 模板库 / 03 导入向导**。

所以 Amor 实际选的是「**编辑器长什么样**」，不是"三套完全不同的产品"。**这句话必须主动说，否则"三套差不多"会被当成做错了的证据——它其实是设计系统收敛的证据。**

## 10. 高度断点是硬需求

B 的 07 面板在 1366×768（视口高 660）上不可用：40+32+28+240 = 340，纸只剩 320，"把出血行滚到面板上沿之上 80px"这个方程无解。
→ <800 面板 ≤200 且可折叠到 40；<700 只能覆盖式抽屉。

### R3 最终版（覆盖上两次，2026-10-24 三次收敛）

**光按主色明度定方向还不够，要按组件档位分。** 贾思敏实测：EP 的 `light-3`（白混 30%）压白字，B 3.39 / C 3.29 / 现存 3.11 —— **全部破 AA**。所以：

| 组件档位 | hover 规则 | 理由 |
|---|---|---|
| **实底主按钮**（白字） | **压暗 8%**；主色 L* < 20（如 A 的墨黑）时**不改色，改用 1px 亮描边** | 变暗让白字对比度**上升**，永远安全；近黑压暗不可辨，改用形状通道 |
| **ghost / secondary**（文字、描边） | **变亮**：底 → light-9，文字 → primary | primary 在 light-9 上 B 5.62 / C 5.33，安全 |
| **EP 实底按钮** | **必须覆写 `--el-button-hover-bg-color`** | 它默认就是 light-3，不覆写直接 3.1–3.4 |
| `--rc-color-primary-active` | 直接用 dark-2（20% 黑），与 EP 对齐，不另设 12% | 少一个自由参数 |

配套：`scrollbar-gutter: stable` 写死在容器上（否则"视口−16"会随滚动条出现而漂移）。

**A 的编号圆点有碰撞成本（+0.3 人日）**：行高 27.5px@100%，60% 缩放时只有 16.5px，而圆点 16px。必须做「按 y 排序 + 最小间距 20px 推挤 + 被推开者加 8px 页边短引线」，否则缩到 60% 看整页时批注会糊成一串。
