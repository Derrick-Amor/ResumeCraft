## 1. 为什么要开这个口子

上一轮的 8 张稿，颜色换了四版、圆角改了 2px、加了 2px 位移——**观感几乎没变**。
原因不是设计师不敢改，是**可动的维度已经被锁完了**：

| 维度 | 当前锁定值 | 出处 | 后果 |
|---|---|---|---|
| 中性色 | `#f9f9f9 → #2b2b2b` 六阶 | PRD 6.2 | 整个界面的明度骨架不能重排 |
| 圆角 | 2 / 4 / 8 / 12 | PRD 6.2 | 出不了"圆润"或"硬朗"两种气质 |
| 阴影 | 2 / 4 / 8 / 16 四级 | PRD 6.2 | 出不了"无阴影扁平"或"重浮层" |
| 字号 | 12 / 14 / 16 / 20 / 24 / 28 | PRD 6.2 | 出不了大标题、细密列表两种极端 |
| 间距 | 4px 网格 2–32 | PRD 6.2 | 密度不可调 |
| 动效 | 100 / 150 / 200 / 300ms | PRD 6.2 | 出不了"几乎无动效"或"明显编排" |
| 主色 | 单一主色，静态面积 ≤ 0.42% | 上一轮裁决 | 出不了双色、色块分区、彩色侧栏 |
| 布局 | 五区域 44 / 264 / 1fr / 280 / 28 | PRD 6.3 | 尺寸区间只有 ±20px，等于固定 |

**结论：这套规则适合"收敛"，不适合"探索"。** 之前把所有探索都塞进收敛规则里做，所以每一版都长得像上一版。

## 2. 探索期临时解禁（本轮有效，选定后全部回收）

- **中性色**：可重排明度骨架，可出现暖白 / 冷灰 / 深色区块（但仍需保证正文可读）

## 6. 结构红线（2026-10-24 定，三套方案都必须遵守）

1. **A4 纸宽 794px 是常量。** 宽度不够时，面板**覆盖**纸，不许**挤压**纸。
   验收：1280 视口下纸的渲染宽度必须 = 794（`getBoundingClientRect().width`）。
2. **Paper 与 CanvasOverlay 必须是兄弟节点。** 选中框、插入线、角标、辅助线一律画在 overlay 层，
   不得进入纸的 DOM；overlay 元素带 `data-export-hide`。
   验收：导出快照与纸节点快照 diff = 0。
3. **07 溢出处理不用 modal**（2026-10-24 裁决）。它要回答"这几行往哪让"，用户必须同时看到出血行与三个选项。
4. **hover 只允许改色/边框**；任何"揭示新内容"必须由 focus 或 click 触发（键盘可达）。
5. **主色必须 9 档一起改**（primary / light-3/5/7/8/9 / dark-2 / subtle），只改 3 个会让 EP 的 hover/disabled 留旧色。
6. **界面字体 ≠ 纸面字体**：`--font-ui-*` 与 `--font-paper-*` 分开命名、永不互相引用。界面标题可用子集化衬线；纸面必须完整字重嵌入，否则导出 PDF 会 fallback。
7. **图标只有 16 / 24 两档**，锁 Lucide 1.5px；业务代码禁用 `el-icon`（它自带 font-size / vertical-align / display 三层叠加会毁对齐）。20px 档砍掉——1.5 的 stroke 在 20 档实际只有 1.25px，1x 屏发虚。
8. **正文 ≥12px 且 ≥4.5:1**；mm / pt 是真值，px 只在 100% 缩放时标注（`px@100%`）。页面上禁止出现假的比例数字。
9. **溢出处理界面永远贴底**：溢出的语义就是"超出页底"，界面跟着语义走，不做居中弹窗、不做自动翻边。

| R5 | A 检查态 1280 装不下（差 2px） | A 检查态右栏 **320 → 296** | 56+24+794+24+296+16(滚动条) = 1210 < 1264，余 54 |

### R3 修正（2026-10-24 二次裁决，覆盖上表 R3 的"统一变亮"）

**不批"全局把 hover 改成变亮 12%"**，因为它会在中明度主色上打穿白字对比度：

| 主色 | 变亮 12% 后 | 白字对比 | 判定 |
|---|---|---|---|
| `#107093`（现） | `#2d81a0` | **4.41** | ✗ 破 AA |
| `#191a1c`（A） | `#353738` | 11.5 | ✓ |

正解是**方向由明度决定，不由偏好决定**：

> `--rc-color-primary-hover` = 主色 **L\* ≥ 20 时压暗 8%**（保对比度）；**L\* < 20 时提亮 12%**（压暗在近黑上 ΔL* < 0.5，看不出）。
> `--rc-color-primary-active` 同理，幅度加倍。
> EP 的 `el-button--primary` 仍按 R3 禁用；其 light-3（+30% 白）只服务 disabled/plain，不参与 hover。

结论：**现存 `tokens.css` 不改**（`#107093` L\*=38，压暗是对的）；只有采纳 A 时，A 的色板用提亮分支。

## 8. 变量分组（2026-10-24 补，四组互不引用）

| 组 | 前缀 | 为什么必须独立 |
|---|---|---|
| 界面字体 | `--font-ui-*` | 只服务 chrome，可子集化 |
| 纸面字体 | `--font-paper-*` | 必须完整字重嵌入，否则导出 PDF fallback |
| 浅底语义色 | `--color-*-on-light` | 现有四色（4.5:1 达标）只对白/浅底成立 |
| 深底语义色 | `--color-*-on-dark` | 警告 `#a86400` 在 `#151A1D` 上只有 **3.74:1**，必须换 `#D99A4E`（7.25:1） |

> 教训：一份语义色不能同时服务浅底和深底，就像一份字体不能同时服务屏幕和 PDF。

07 收敛成"贴底"之后，8 屏里 **04/05/06/07/08 五屏在三套方案之间同构**，真正分得开的只有 **01 编辑器 / 02 模板库 / 03 导入向导**。

## 10. 高度断点是硬需求

B 的 07 面板在 1366×768（视口高 660）上不可用：40+32+28+240 = 340，纸只剩 320，"把出血行滚到面板上沿之上 80px"这个方程无解。
→ <800 面板 ≤200 且可折叠到 40；<700 只能覆盖式抽屉。

### R3 最终版（覆盖上两次，2026-10-24 三次收敛）

**光按主色明度定方向还不够，要按组件档位分。** 贾思敏实测：EP 的 `light-3`（白混 30%）压白字，B 3.39 / C 3.29 / 现存 3.11 —— **全部破 AA**。所以：

| 组件档位 | hover 规则 | 理由 |
|---|---|---|
| **实底主按钮**（白字） | **压暗 8%**；主色 L* < 20（如 A 的墨黑）时**不改色，改用 1px 亮描边** | 变暗让白字对比度**上升**，永远安全；近黑压暗不可辨，改用形状通道 |
| **ghost / secondary**（文字、描边） | **变亮**：底 → light-9，文字 → primary | primary 在 light-9 上 B 5.62 / C 5.33，安全 |
| **EP 实底按钮** | **必须覆写 `--el-button-hover-bg-color`** | 它默认就是 light-3，不覆写直接 3.1–3.4 |
| `--rc-color-primary-active` | 直接用 dark-2（20% 黑），与 EP 对齐，不另设 12% | 少一个自由参数 |

配套：`scrollbar-gutter: stable` 写死在容器上（否则"视口−16"会随滚动条出现而漂移）。

**A 的编号圆点有碰撞成本（+0.3 人日）**：行高 27.5px@100%，60% 缩放时只有 16.5px，而圆点 16px。必须做「按 y 排序 + 最小间距 20px 推挤 + 被推开者加 8px 页边短引线」，否则缩到 60% 看整页时批注会糊成一串。

## 11. A 方案最终修正（2026-10-24，对定稿的修补，非新工作）

1. **页边注不挪走，拆成两半**：页边放「1px 竖线 + 16px 编号方框」（本质是印刷套准线，**占宽 0**，在既有 24px 沟槽内）；纸底放「校样条」（794 宽、与纸齐边、等宽排版 `01 │ 第 2 页 · 第 14 行 │ 描述 │ 处理`）。两者双向联动。
   → A 的独有语法保住了：**只有 A 有"一条从纸边指向正文的竖线"**，B 的页签是横的、C 的抽屉是块的，复制不了。
2. **删除横向刻度尺**：纸恒 794、x 无可调自由度，量常量的尺子是装饰不是测量。**24px 沟槽既是刻度位也是页边标记位**——纸外所有非纸内容共用这一条 24，这是 A 与 B/C 的真正分界。
3. **272 右栏改三列栅格**：`label 88 / 数值 104 / 单位 32` + 下划线，**不设常驻 step 块**（用 ↑↓ 与横向拖拽），否则 144px 内贴边。日期类长值单独走日期选择器。

### R3 补丁：A 的实底按钮 hover 单列（2026-10-24 批准）

| 方案 | 实底主按钮 hover |
|---|---|
| A（墨黑 `#191A1C`） | **不变色，1px 亮描边 `#3A3D42`** |
| B / C（L*≈40） | 压暗 8%（白字升至 7.34 / 6.70） |

理由不是可辨性（提亮 12% 也可辨），是**系统内部一致性**：A 全案只有纸一层阴影、层级靠边框，hover 用边框提亮是它自己的语法。其余两格与 `-active = dark-2` 不变。

**A 的批注圆点三条定死**：① 锚纸边不锚沟槽（1440 居中时沟槽 24→151，锚沟槽会让圆点离纸 147px）；② 圆点里放**批注序号**不放行号（行号每次重排都变，无法口头引用、无法落号）；③ 右栏 272 是「规格 / 批注」两 tab，三列栅格已占 256，只剩 16。

### R3 收口（2026-10-24 第四次，以此为准）

1. **不做"禁 el-button primary"禁令**，改为桥接层覆写 `--el-button-hover-bg-color` / `--el-button-active-bg-color`（+0.1 人日，非 `:deep`）。
   理由：`ElMessageBox.confirm` 内部渲染的就是 primary 按钮，禁令会逼着自建 ConfirmDialog（焦点陷阱 + Esc + 键盘）；而覆写让 EP 的 primary 自动合规，便宜 4 倍。
   **若将来要禁，理由是视觉（MessageBox 做不出 A 的 1px 线 + 无圆角），不是 hover。**
2. **EP 的 hover 到底指向哪个变量，不做断言，改成可执行自检**：
   > 实现第一个 EP 主按钮时，在 devtools 读 `.el-button--primary:hover` 的 computed `background-color`；若等于 `--el-color-primary-light-3`，则在桥接层覆写两个按钮级变量。
   这条同时是"EP 升级必跑的三张快照"之一。
3. **A 的沟槽分工修正**：竖尺需要 20–22px（数字 + 刻度）且贯通连续，准线标记需要 24px（1px 线 + 3 + 16 方框 + 4），两者在同一沟槽里必然互相遮挡。
   → **左沟槽放竖尺（唯一一条），右沟槽放准线标记。** 左 24 + 右 24 本就在 1170 内，零宽度代价，且更像真校样（左量位置、右写校改）。

### R3 再收口：A 的 hover **不特批**，回到提亮 12%（2026-10-24 最终）

前一条「A 用 1px 亮描边」**作废**。贾思敏实测否掉了它：

| 方案 | 状态可辨性 | 判定 |
|---|---|---|
| 描边 `#3A3D42` 对填充 `#191A1C` | **1.59:1** | ✗ WCAG 1.4.11 要求状态指示 ≥3:1；要达标得亮到 `#6C6F74`（3.45:1），那时描边抢戏 |
| 提亮 12% → `#363737` | L* 9.2 → 22.5，**ΔL\* 13.3**，白字 12.1:1 | ✓ 可辨且零风险 |

**裁决：A 走提亮 12%，不开特例。** 理由不是观感，是两条硬账：① 描边方案本身不满足状态对比度；② 一旦给 A 开"我这套可以破例"，后面每套都会来要例外，规则就废了。

"hover 褪色"这个观感问题**不用加字重解决**——字重变化会让按钮文字宽度跳动，在定宽按钮里是新的抖动源。

### 成本定稿：A = 2.5–3.0 人日（2026-10-24，07 形态拍定）

前两次给 Amor 的 A 成本（2.2–2.7 / 3.0–4.2）都不准，原因是 07 的形态没定。现在定了：

**07 并入纸底校样条，放弃"三张选项卡"。** 理由不是省钱，是语法自洽：
- 校样单的本义就是「一行一个问题」，三张选项卡是**对话式**语法，那是 B 和 C 的语法，不是 A 的；
- 并条之后"A 的批注条"和"溢出条"是同一条，同号对应，**A 的页边准线一套就够**；
- 连带删掉"翻边只在 open 时决策一次"这条规则——不再有浮层，就没有翻边。

| 方案 | 定稿成本 |
|---|---|
| **A** | **2.5–3.0 人日** |
| **B** | 1.7–2.2 |
| **C** | 2–3 |

B 仍然是三套里最便宜的，但三套差不到 1.8 倍——**不足以成为选择理由**。

### 两项最终修正（2026-10-24，覆盖前面所有相关裁决）

**1）hover 的度量从"提亮 12%"改成"目标 ΔL\* = 6–8"。**

理由：同一个百分比在深色上换算出的感知差是浅色的两倍多。

| 主色 | 提亮 12% 后 | ΔL\* |
|---|---|---|
| `#191A1C`（A） | `#353637` | **13.3** —— 在近黑按钮上不像"悬停"，像"换了颜色" |
| B/C 的压暗 8% | — | 6–8 |

改成 ΔL\* 6–8 后三套落在同一感知区间，**这不是给 A 开特批，是把度量从百分比换成感知量**。

**2）07 砍掉"纸面幽灵预览"，改用「虚线分页线」。**

- 幽灵预览要求排版引擎有 dry-run（只算不提交），而引擎现在还不存在（`src/` 一屏未实现）；
- 即便做出来，幽灵与真实排版会差 1–2px（字体未加载完、测量取整），用户逐像素比对后就不再信任它，**比没有更糟**；
- 每次点选项都要重算一次排版。

替代：**纸面画一条虚线标出分页线会落到哪**（overlay，不打印），成本 0.2，零风险，不依赖引擎。这也更合 A 自己的语法——**裁切标记是线，不是鬼影**。

**A 成本借此定死：3.2–3.4 人日**（前面 3.1–3.3 作废：漏算 07 的原位横向选项卡 0.3）。

### 三点收口（2026-10-24，最终）

**1）幽灵预览：P0 明确不做，不留中间价。**

| 选项 | 07 成本 | A 合计 | 结论 |
|---|---|---|---|

### 最后一版：hover 幅度与 A 成本（覆盖前面所有相关段落）

**1）"统一目标 ΔL\* 6–8"作废**——设计师复算指出不可行：B `#146B45` 压暗 8% 只有 ΔL\* **3.2**，要拉到 6–8 得混黑 **37%**，那不是悬停，是换品牌色。根因是 L\* 曲线在近黑陡、中明度缓，同一 ΔL\* 两端的百分比差 5 倍。

**最终规则（方向 + 幅度分开定）**：

| | 方向 | 幅度 | 实得 ΔL\* |
|---|---|---|---|
| A（L\*≈9） | 提亮 | **6%** → `#272829` | 6.7 |
| B / C（L\*≈40） | 压暗 | **8%** | 3.2（刚过 JND，配合边框/底色变化足够） |

> 判据不是"同一个 ΔL\*"，是"**落进 3–7 的可辨区间**"。百分比是手段，ΔL\* 是验收口径。

**2）A 成本取两位专家估算的高值，避免低估：A = 3.2–3.4 人日。**

**3）「纸外」规则补上纵向一半**：
