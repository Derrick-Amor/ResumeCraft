## 1. 工期口径（Q1 决策：只排工期，不设截止日期）

Amor 决策（2026-10-23）：本项目是个人变现开发项目，与毕设排期无关，**不设里程碑截止日期**；AI 辅助下可能提前完成；时间表按实际完成情况滚动更新。

据此定三条规则：

1. 下表「建议工期」是**排产参考，不是承诺**，单位＝有效工作日（不含 Amor 审稿等待、样本提供等待、TAPD 故障等外部停顿）。
2. 实际用时单独记录在「实际」列，每次偏差超过估算 30% 时，我更新本表并同步调整 TAPD 迭代起止日期。
3. TAPD 迭代**必须有起止日期**（平台要求）。因此建迭代时填「估算窗口」并在迭代描述里写明"估算锚点，随实际滚动更新"，不当作承诺日期；不制造"已逾期"的假信号。

## 2. 「每阶段预留 20% 集成回归」怎么用（具体化，不停留在口号）

| 里程碑末 | 回归内容 | 谁做 | 判定 |
|---|---|---|---|
| M0 | 四门空跑 + `verify:*` 占位链路 | fe-foundation | 命令全绿 |
| M2 | 全量单测 + 三阶段溢出临界样本（压缩/拆分/下移各一） | fe-layout | LayoutResult 快照两次一致 |
| M3 | 中英各一份 PDF/DOCX 导出回归 + 模板切换零丢失回归 | fe-io + fe-content | 回读冒烟 + 人工抽验 |
| M4 | E2E 三引擎 + 视觉基准 | qa | 基准锁定且 CI 可跑 |
| M5 | PRD 14.3 发布阻断条件逐项清零 | doc + 阿U | 逐条勾选有证据 |

**纪律**：进入"集成回归"时间段后**不接新卡**，只做拼装、回归、补测试。若回归暴露缺陷，按"退回原卡 Agent、附错误原文、上限 2 次"处理。

## 3. 每个里程碑的验证方式（一条命令 + 一项人工）

| 里程碑 | 一条命令 | 人工项（必须 Amor 参与） |
|---|---|---|
| M0 | `pnpm lint && pnpm type-check && pnpm test && pnpm build` | 确认执行计划包（本文件 + TASKS + CONTRACT） |
| M1 | `pnpm test -- src/model src/ui/controls` | 用浏览器打开 `docs/design/mockups/index.html`，确认视觉基调与 token 数值表 |
| M2 | `pnpm verify:layout` | 无（只看门是否达成） |
| M3 | `pnpm verify:export` | 自己导一份中文 PDF、一份 DOCX，在 WPS/Word 打开看 |
| M4 | `pnpm verify:import && pnpm test:e2e` | 用一份真实简历文件试导入 |
| M5 | 线上地址可访问 + 14.3 清单 | 发布决策 |

> `verify:layout / verify:export / verify:import` 的具体参数与实现由 TC-002 建立骨架、后续各卡填充；TASKS.md 在该卡交付后回填实际命令。

## 4. 变更控制（谁改、怎么改）

| 类型 | 判据（满足任一即升级） | 处理 |
|---|---|---|
| 小改 | 不新增模块目录、不改 `src/model/` schema、不影响超过 2 张未开工卡、不动核心闭环 | 我更新 TASKS.md + CONTRACT 变更记录，继续执行 |
| 大改 | 新增模块/新增 schema 字段来源/影响 ≥3 张卡/改核心闭环（新建→编辑→导出）/动 PRD 已锁定决策 | 出变更单（现状/影响/替代方案）→ Amor 拍板 → 回写 PRD 或任务分工 → 更新计划包 |

**红线**：任何情况下不由我或子 Agent 直接改 PRD 已锁定决策；契约没改而代码先改，一律打回。

## 5. 风险与缓解（执行层，非 PRD 第 20 章重复）

| # | 风险 | 首次暴露点 | 缓解动作 |
|---|---|---|---|
| 1 | Canvas2D 测量与 DOM 渲染行盒不一致（PRD 13.2#1），可能推翻测量方案 | TC-006 | 该卡第一件事就是做对照小样，结论写 `docs/verify/canvas-vs-dom.md`；不通过则升级变更单，绝不带病进 TC-007 |

| 4 | 环境：pnpm 未安装；GitHub 远端已有 `Initial commit`（仅 LICENSE） | TC-002 | pnpm 用 `corepack enable` 启用；仓库不裸 `git init`，改为 `git init -b main` + `git fetch origin main` + `git reset --mixed FETCH_HEAD` 保留远端历史后首提交 |
| 5 | 主控上下文膨胀导致遗忘约定 | 每 2–3 卡 | 按 TAPD 规范 §11 写 `docs/plan/PROGRESS.md` 快照 |
| 6 | 单卡过大导致反复打回 | 任意 L 卡 | 只允许卡内拆子步，不新开卡逃避验收（任务分工 §5） |

## 6. 记账与三方对账

- TAPD＝状态机（谁在做、做到哪）；`TASKS.md`＝镜像（TAPD 降级时升主账）；git＝代码事实。
- 每卡闭环：TAPD 状态流转 + 评论贴 `docs/handoff/TC-XXX.md` 路径；同时更新 TASKS.md 该行状态。
- 每里程碑结束：TAPD 状态 = TASKS.md = git 实际代码，三方不一致先查清再继续，并输出阶段报告。
