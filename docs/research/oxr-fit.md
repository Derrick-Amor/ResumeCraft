# OXR 契合性评估（2026-10-27）

> 结论先行：**现在不接。它解决的是 PRD 里我们主动砍掉的那个问题。**
> 但契约 §7 的 `RecognitionProvider` 插槽必须留好，M6 后端就绪后再评估。

---

## 1. OXR 是什么

**Optical Everything Recognition**，上海 SoMark 团队 2026-10-20 开源的文档解析模型（1.3B 参数）。

- 把 PDF / 文档图片转成 **带版面坐标与阅读顺序的 Markdown / JSON**
- 识别 13 类元素：表格→HTML、公式→LaTeX、化学式→SMILES、代码块、印章、页眉页脚等
- 架构特点：版面分析（LA）独立可插拔，识别 + 阅读顺序合并进主模型
- 许可：Apache 2.0 变体，**融资/年营收 < 200 万美元免费商用**，禁止用它提供竞品托管 API
- 资源：[GitHub](https://github.com/SoMarkAI/OXR) ｜ [HuggingFace](https://huggingface.co/SoMarkAI/OXR-1.0)

### 证据等级（务必分清）

| 可采信 | 厂商自述，未经第三方复测 |
|---|---|
| 开源行为、仓库与权重公开 | 三榜第一：OmniDocBench 97.18 / olmOCR-Bench 87.84 / DocParsingBench 87.76 |
| 发布时间、免费 API 存在 | 100 页 101 秒（RTX PRO 6000） |
| 社区反馈（一周 1100+ Star） | RSI 训练范式的收益比例 |
| 官方演示与第三方上手实测 | 领先第二名的幅度（官方柱状图纵轴从 85 起画，实际只领先 0.2–1 分） |

## 2. 决定性事实：OCR 不在我们 P0 范围内

`docs/plan/TASKS.md` §3 导入样本清单写得很明确：

> 扫描型 PDF：无文字层的扫描件 → **仅验证「正确提示是扫描件」，不做 OCR**

产品层面**根本没打算做 OCR**。OXR 要替代的那个能力，我们在需求阶段就砍掉了。

而 TC-012 导入层走的是 `mammoth`（DOCX 结构）+ `pdfjs-dist`（PDF 文本层），两条路都不需要识别。

---

## 3. 真正的契合点（值得记）

如果将来做扫描件导入，OXR 比传统 OCR 合适，原因是**输出结构对得上**：

契约 §7 定义了 `ImportReport{ blocks[], confidence, pending[], warnings, sourceKind }`，
OXR 输出的 JSON 正好是「带版面坐标的块 + 阅读顺序」。

**这比"识别准"更重要**：简历导入最难的从来不是认字，是把字还原成
「哪段是项目名、哪段是描述、顺序是什么」。OXR 直接给出这个结构。

---

## 4. 三个现实障碍

| 障碍 | 说明 |
|---|---|
| **P0 无后端** | 契约 §0.5：前端 MVP 无 HTTP。本地跑不了 1.3B 模型 |
| **需要 GPU** | 官方 24GB 显存起（低并发），推荐 48GB+；有实测称 RTX 3060 级可跑但慢 |
| **免费 API 不建议生产** | 官方原话"至少在服务器负载仍能承受的区间内维护"，随时可能关 |

## 5. 对我们特别有利的一点

**许可区间**：200 万美元以下免费商用——毕业设计、个人项目完全够用。

**自托管**契合隐私路线：产品定位是「简历不云存」，OXR 跑在本机，简历不出机器。
这条比调云端 OCR 更符合产品定位。

---

## 6. 实测短板（与简历场景相关）

第三方在 4090 上跑了 18 个案例（2026-10-25 报告）：

- **生僻字大面积失败**（与 Paddle 相当）
- **竖版内容会漏**
- **跨页表格断成两段**（Paddle 反而能拼成一张）

而 OXR 的强项——复杂表格、公式、化学结构式、多栏论文——**简历场景基本用不上**：
简历是单栏、结构简单、几乎没有公式。

**对我们的实际价值只有两件事：扫描件识别、版面坐标 + 阅读顺序。**

---

## 7. 决策

| 时点 | 动作 |
|---|---|
| **现在（P0）** | 不接。不改任何计划。只保证 `RecognitionProvider` 接口存在 |
| TC-012 做导入层时 | 把 OXR 作为 `RecognitionProvider` 的**可切换实现**预留，不硬编码进主流程 |
| P0 主路径 | 继续 `mammoth` + `pdfjs-dist`（快、零依赖、离线） |
| 扫描件 | 照旧只提示「这是扫描件」 |
| **M6 后端就绪后** | 用自己简历样本实测准确率 → 决定是否自托管 → 评估并发 |

**一句话**：OXR 是好东西，但解决的是我们主动砍掉的问题。现在什么都不用动，
契约里 `RecognitionProvider` 已经是为这类模型准备的插槽。
